# 工程规范采用声明

采用 X-Gen 工程规范 1.0.0，权威来源为 xgen-roadmap 提交 `c018272a1bfa0a0ad0e811ceedcb22862640ed98` 的 `docs/standards/README.md`。该提交目前仅为本地基线，未假设远端链接已可访问；正式公开交付前需提供可获取的固定来源。本文只记录采用情况，规范正文仍由 roadmap 维护。

## 范围与配置

- 自有生产 C、公开头、测试、构建、脚本和文档采用相应规则。
- 根 `.clang-format`、`.editorconfig` 是 Nexus 基线的受控副本；无本地格式覆盖，工具版本由固定 xgen-quality 包统一维护。
- 生产 C11 与主机 C++17 分开；GoogleTest 固定测试依赖，不出现在生产导出中。
- 质量工具固定版本，以 `tools/quality.py` 作为本地、pre-commit 与 CI 的唯一检查入口。
- `out`、开发依赖、第三方与生成物不作为自有文本格式检查输入；生成公开版本头仍通过 C/C++ 包含和安装消费检查。

## 自动检查与人工验证

| 范围 | 采用方式 |
| --- | --- |
| 文本与配置 | UTF-8、LF、尾空格、冲突标记、JSON/YAML 语法 |
| 排版 | 固定 clang-format 与 Nexus 配置 |
| 公开 API | 检查公开头的 Doxygen 文件入口，严格 Doxygen 检查声明，加所有权、seed、NULL 与并发契约评审 |
| 行为 | GoogleTest 调用真实生产库；固定输入和独立参考验证 |
| 消费边界 | 源码、安装、单算法、缺失/未知组件、版本及 C/C++ 头验证 |
| 静态分析 | 真实编译数据库筛选生产翻译单元，分别运行 Cppcheck 和 clang-tidy |
| 覆盖率 | 自有生产源码行、函数和分支分别至少 80%，保留完整行/分支报告 |
| 检查器可靠性 | Python 单测及真实失败命令，验证错误向上传递 |

首次 CRC 试点验证了仓库内检查器；随着 bytes/status 提取，通用实现、回归和默认策略已迁入独立 xgen-quality。当前只保留 `tools/quality.py` 薄入口与模块配置，显式安装固定的工具包后执行检查；生产构建不依赖该开发工具。

上述自动检查对应 QUAL-001 至 QUAL-008、TST-006、TST-012、TST-014；源码和配置摘要对应 QUAL-013 的单仓部分。接口语义、TDD 过程、来源授权和跨平台声明仍需结合评审与实施记录，不由单个绿色命令替代。跨仓依赖及产品交付证据在相应接入任务补齐。

## 适用限制

本仓库是无硬件依赖的库，不声明完整 MCU 镜像、Boot 分区或实时上界，因此对应产品验收留在产品仓库。没有用此限制豁免本库的输入、内存和行为验证。

未设代码质量诊断豁免。源码许可证待确认属于发布未完成项，不标记为许可证检查已通过。当前远端 CI 和公开发布状态以及本地结果见 [实施记录](implementation-log.md)。
